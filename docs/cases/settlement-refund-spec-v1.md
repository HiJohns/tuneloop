# 结算退款算法规格 v1（草案 · 待确认）

> 来源：#2339 结算三例失败（`TestRefundDiff_*` / `TestSettlementFlow`）的逐行追踪。
> 现状：产品 `computeSettlement` 把押金当折扣、用「实付/标价」倒推日租，导致多退 466.67 元/单。
> 关联：`docs/cases/settlement-accounting-rules.md`（#2268 P1，§1 已确认 `cash_paid` = 现金净实收**含押金**）。
> 状态：**草案，未经 Owner/专家确认前不得据此改码**。

---

## 0. 三条基本原则（本规格的根）

| # | 原则 | 说明 |
|---|---|---|
| P1 | **押金 ≠ 折扣** | 押金是保证金：下单时收取、归还时原路退还（可扣逾期/定损/物流），**永不参与租金折算**，也**不作为乐币抵扣基数** |
| P2 | **应付租金按标价计费** | 租金 = 「标价日租 × 实际计费天数」（含阶梯折扣），**不得**用「实付租金 ÷ 标价」倒推出的有效日租 |
| P3 | **乐币只抵扣租金，且有上限** | 上限 = `floor(实际租金 × pay_ratio)`；已用超出上限的部分**退乐币**；未用满的部分**不折现** |

> P2 是本次缺陷的核心：现实现用 `paid/original = 2500/3000 = 0.8333` 当折扣率摊到每天，把押金 500 变成了 16.7% 的「假折扣」。

---

## 1. 符号定义

| 符号 | 含义 | 来源 |
|---|---|---|
| `L` | 标价日租（阶梯档位原价） | `pricing_breakdown.tiers[].daily_rate` |
| `R_list` | 合同标价租金（下单时） | `Σ tier_segments`（合同天数） |
| `deposit` | 押金（全额档/差额档实收值） | `orders.deposit` |
| `p_used` | 已使用乐币 | `orders.gift_points_used` |
| `ratio` | 乐币抵扣比例上限 | `gift_policies.pay_ratio`（可配置，**禁止硬编码**） |
| `actualDays` | 实际计费天数（提前归还按实际天数；逾期按合同天数 + 逾期天数，另计逾期费） | 结算入参 |
| `R_actual` | 实际标价租金 = 按同一阶梯规则重算 `actualDays` 天 | `Σ tier_segments(actualDays)` |
| `deductions` | 现金扣款 = 逾期费 + 定损 + 物流费 | `damage_reports` / 结算入参 |
| `cash_paid` | 现金净实收（**含押金**，不含乐币） | `orders.cash_paid`（#2268 §1） |

## 2. 算法（6 步）

```
① 实际租金      R_actual   = 标价重算(actualDays)          // P2：用标价，不用实付倒推
② 乐币上限      cap        = floor(R_actual × ratio)      // P3：基数为实际租金，不含押金
③ 乐币退款      p_refund   = max(0, p_used − cap)         // 超用才退，未用不折现
④ 乐币承担租金  p_borne    = p_used − p_refund
⑤ 现金结算      cash_refund = cash_paid − (R_actual − p_borne) − deductions
                             // 负数 = 需补缴（payable_shortfall = −cash_refund）
⑥ 押金处理      押金已含在 cash_paid 中：扣款(deductions) 从押金优先扣，
                 押金不足时体现为 ⑤ 的补缴；押金余额无需单独公式
```

### 输出

| 字段 | 公式 |
|---|---|
| `rent_payable` | `R_actual`（标价，供账单展示） |
| `gift_points_refunded` | `p_refund` |
| `cash_refundable` | `max(0, cash_refund)` |
| `payable_shortfall` | `max(0, −cash_refund)` |
| `deposit_refund`（展示用） | `min(deposit, max(0, cash_refund))` 概念拆分，不参与计算 |

### 守恒式（规格级不变量）

```
cash_refund + p_refund = cash_paid + p_used − R_actual − deductions
```

即：**退的钱 + 退的点 = 已付价值 − 实际消费 − 扣款**。任何实现都必须满足（含 0 元与补缴场景）。

## 3. 推演样例（标价 ¥100/天，合同 30 天，押金 ¥500，ratio = 0.3）

| # | 场景 | cash_paid | p_used | actualDays | R_actual | cap | p_refund | cash_refund | 合计退还 |
|---|---|---|---|---|---|---|---|---|---|
| T1 | 不用乐币，28 天 | 3500 | 0 | 28 | 2800 | 840 | 0 | **700** | 700 |
| T2 | 用 500 点，28 天 | 3000 | 500 | 28 | 2800 | 840 | 0 | **700** | 700 |
| T3 | 用满 1000 点，28 天 | 2000 | 1000 | 28 | 2800 | 840 | **160** | **40** | 200 |
| T4 | 用满 1000 点，当日取消 | 2000 | 1000 | 0 | 0 | 0 | **1000** | **2000** | 3000 |
| T5 | T3 + 定损 300 | 2000 | 1000 | 28 | 2800 | 840 | 160 | **−260（补缴）** | 160 点 + 补缴 260 |
| T6 | T3 + 定损 800（超押金） | 2000 | 1000 | 28 | 2800 | 840 | 160 | **−760（补缴）** | 160 点 + 补缴 760 |
| T7 | 续费 +30 天（6000 标价），实际 45 天 | 5500 | 1000 | 45 | 4500 | 1350 | 0 | **2000** | 2000 |
| T8 | 优惠券 300（券后 2700），28 天 | 3200 | 0 | 28 | 2800 | 840 | 0 | **400** | 400 |
| T9 | 零押金乐器（deposit=0），T3 条件 | 2000 | 1000 | 28 | 2800 | 840 | 160 | **40** | 200 |
| T10 | 差额押金 30（deposit=30），T3 条件 | 2030 | 1000 | 28 | 2800 | 840 | 160 | **70** | 230 |

> 说明：
> 1. T1/T2 的「合计退还」相同（700）是因为 `cash_paid + p_used` 恒为 3500 —— 守恒式的直接结果：**总退款与实际用多少乐币无关，只改变形态（现金 vs 乐币）**。
> 2. **T3/T9/T10 的前提**：夹具中 `cash_paid = 2000` 按 §1「含押金」解读，即租金现金 = 1500（押金 500）。
>    于是「租金价值已付 = 1500 + 1000 乐币 = 2500 < 标价 3000」，属**真实少付 500**，故只退 200。
>    若业务要求下单必须足额收齐（`cash_paid = 标价租金 − 乐币 + 押金`），这三行应改为 `cash_paid=2500/2000/2030`，对应退款 540/40/70 —— 见 **Q8**。

## 4. 现行实现的偏差（需修）

| 位置 | 现行 | 规格 | 影响 |
|---|---|---|---|
| `user_settlement.go:817` | `totalRentPaid = cash_paid + prepaid + gift − deposit` 后当作「实付租金」 | 押金不参与租金计算（P1） | 制造 500 元「假折扣」 |
| `segment_settlement.go:186` | `rate = paid / original`，用 `OriginalDaily × rate` 计息 | 直接按标价 `OriginalDaily` 计息（P2） | 28 天从 2800 变 2333.33 |
| `user_settlement.go` 净额段 | `netYuan = discountedDue − paidTotal`（paidTotal 含押金） | `cash_refund = cash_paid − (R_actual − p_borne) − deductions` | 退 666.67（应 200） |
| 乐币上限 | 支付端按「支付金额（含押金）×ratio」，结算端按「租金×ratio」 | 统一按「实际租金 × ratio」，不含押金 | 两侧上限不一致 |

## 5. 待确认清单（专家逐条打勾）

| # | 问题 | 建议值 | 状态 |
|---|---|---|---|
| Q1 | 乐币上限基数：**实际标价租金** vs 券后租金 | 实际标价租金（券是价格优惠，不影响乐币额度语义） | ⬜ 待确认 |
| Q2 | 舍入：`floor` 到整数点；现金保留 2 位；分差归平台 | floor | ⬜ 待确认 |
| Q3 | 扣款顺序：逾期 → 定损 → 物流；押金不足则补缴 | 同建议 | ⬜ 待确认 |
| Q4 | 扣款（逾期/定损/物流）超出「押金 + 现金余额」时，押金是否可用于抵扣**租金**缺口 | 押金只承担逾期/定损/物流；不足部分走补缴，不抵租金（T5/T6 口径） | ⬜ 待确认 |
| Q5 | 续费单：乐币上限按「整单汇总租金」还是「逐期分别计算」 | 整单汇总（与支付端一致） | ⬜ 待确认 |
| Q6 | 历史已结算订单是否按新规格重算 | **不重算**（仅新结算生效，避免对账断裂） | ⬜ 待确认 |
| Q7 | 「先退乐币」原则是否废止 | 以本规格 §2 第③步为准（仅超额退点） | ⬜ 待确认 |
| Q8 | 下单是否必须**足额收齐**（`cash_paid` = 标价租金 − 乐币 + 押金）；历史上少付的单据按「少付即少退」处理还是补收 | 新单足额；历史单不追溯 | ⬜ 待确认 |
