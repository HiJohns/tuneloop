# 受控商户中转物流设计

> 适用范围：租赁订单中**受控商户**（merchant_type=controlled）的实物流转与信息隔离。
> 权威规则另见 `cases.md §4.1.5`（创建/路由/角色三要素）与 `state-machine.md §4.2/§5`（可见性、转发会话）。
> 本文档补充：会话状态与段映射、物流费分段与承担、中转网点配置字段、中转工作台交互。

## 1. 概念

- 受控商户不直接接触顾客：实物一律经**中转网点**与顾客之间流转，双方信息双向隔离。
- **订单侧只暴露两档物流语义**，段级状态 ALL 放在中转会话（`ForwardingSession`）：
  - 外发（outbound）：订单展示「**已发货**」
  - 归还（return）：订单展示「**归还中**」
- 不新增订单主状态（订单仍 `shipped` / `returning` 等既有主状态机）；流转明细由会话派生字段承载。

## 2. 中转会话状态与段映射

复用现有 `ForwardingSession` 状态常量（pending/in_transit/received/ready/last_mile/completed/lost/cancelled/exception）。

| 方向 | 段 | 会话状态 | 订单展示 | 中转员工可见文案 |
|------|-----|---------|:---:|------|
| outbound | 受控→中转（受控商户发货） | `in_transit` | 已发货 | ①段运输中 |
| outbound | 等待转发（中转已收货） | `ready` | 已发货 | 等待转发 |
| outbound | 中转→顾客（中转 last_mile 发货） | `last_mile` → 顾客确认 `completed` | 已发货 | ③段派送中 ✓送达 |
| return | 顾客→中转（顾客归还发运） | `in_transit` | 归还中 | ①段运输中 |
| return | 等待转发 | `ready` | 归还中 | 等待转发 |
| return | 中转→受控（中转发回商户） | `last_mile` → 商户/验收 `completed` | 归还中 | ③段派送中 ✓送达 |

- `pending`：会话已创建（下单/发起归还时），待发运。
- `received`：中转已收货（含拆箱/拍照），随后员工确认后进入 `ready`（等待转发）。
- 异常（丢失/取消/异常）：`lost` / `cancelled` / `exception`，对顾客仅展示「请联系客服」。

## 3. 物流费分段与承担

新增分段记录（建议表 `transit_shipping_fees`，或 ForwardingSession 增列 + 分段行，实施时定）：

| 段 | 方向 | 录入方 | 承担方 |
|----|------|--------|--------|
| ① 受控→中转 | 外发 | 受控商户发货时录入 | **顾客** |
| ② 中转→顾客 | 外发 | 中转员工 last_mile 发货时录入 | **顾客** |
| ③ 顾客→中转 | 归还 | 顾客归还填单时录入（自付） | **顾客** |
| ④ 中转→受控 | 归还 | 中转员工转发回商户时录入 | **商户承担** |

- **订单详情「物流费」= ①+②+③ 加和（顾客应付口径，单一项展示）**；④ 不计入顾客侧，走商户结算。
- 录入方各自填写物流公司 + 单号（物流公司/单号在场内各段可见，跨角色按可见性规则）。

## 4. 中转网点配置

| 配置项 | 说明 |
|--------|------|
| 基本信息 | 名称 / **地址（必填）** / **电话（必填）** / 联系人（可选）/ 状态；地址电话是物流面单关键（顾客寄收件地址） |
| **成员管理** | 复用 `site_members`（site_id/user_id/role），**角色仅两类：中转网点管理员（`site_admin`）/ 中转网点员工（`site_member`）**（不承接普通网点细分角色）；交互详见 §4.1 |
| 归属 | 平台顶层组织（租户=平台根），平台级「中转中心」管理（创建/编辑/停用 + 路由配置同页） |
| 路由 | TransitRoute（受控网点 ↔ 中转网点）：一受控↔一中转；一中转可服务多受控；`is_default` 标记默认，`priority` 为多候选排序 |

### 4.1 成员管理用例（#1938：与网点成员管理体验一致）

> 入口：中转中心「中转网点」表格行「成员」→ 弹「成员管理」弹窗（复用 `frontend-pc/src/components/SiteMemberManagement.jsx`）。

**UC-1 查看/搜索成员**
- 列表列：姓名 / 邮箱 / 角色 / 加入时间 / 操作
- 搜索框按姓名或邮箱**前端过滤**；空态「暂无成员」
- 数据：`GET /admin/transit-sites/:id/members`（JOIN users enrich `user_name`/`user_email`）

**UC-2 添加成员 — 绑定现有用户**
- 输入用户名 / 邮箱 / 手机之一，失焦调 `GET /users/check?<field>=`；`exists=true` → 标红「已注册」并切「绑定现有用户」确认态（展示只读用户信息）
- 选角色（两类，默认 `site_member`）→ 提交 `user_ids:[{user_id,role}]`
- 唯一性：同一用户已是本网点成员 → 后端 400，前端 `message.error`

**UC-3 添加成员 — 新建用户**
- 输入：用户名* / 姓名* / 邮箱* / 手机*（三项唯一性检查同上）+ 角色 + 「跳过邮箱验证（直接激活）」复选
- 提交 `new_users:[{username,name,email,phone,role}], skip_activation`
- 成功：关闭 + 刷新；`skip_activation` 时**一次性**展示初始密码（`initial_passwords`，copyable）
- 冲突 `40901`：同商户不同网点 → 确认后以 `user_ids` 直接加入；已是本网点成员 → 提示；与商户无关 → 提示联系商户管理员

**UC-4 变更角色**
- 行内 `Select` 即时调用 `PUT /admin/transit-sites/:id/members/:user_id {role}`；成功 toast + 刷新
- 顺序：先 IAM `UpdateUserRoleInOrgWithToken`，成功后更新本地缓存

**UC-5 移除成员**
- 行内「移除」→ Popconfirm 确认 → `DELETE /admin/transit-sites/:id/members/:user_id`
- 按 `site_id + user_id` 归属校验（跨站 404，不误删）

**通用规则**
- 角色仅 `site_admin`/`site_member`；IAM 绑定先行，**失败不写本地缓存**（红线）
- IAM 角色模板失败：`role_errors` 随响应体透出（不静默）
- **复用建户（#2025 D2 裁定）**：手机号已注册 → 不再以 409/40901 阻塞；按 **D2 管理员信任制**直接**复用既有用户 + 新增中转网点 relation**（一人一记录，无 SMS 验证）
- **移除成员（#2025 D4 裁定）**：删除中转网点 relation（用户记录保留、可重新加回）

## 5. 中转员工工作流（小程序 + PC）

**外发（outbound）**：
1. 会话查找：中转工作台「扫码 / 输入短码或单号」→ 命中会话卡（含顾客收件信息与物流留言）——session_code 6 位短码或 TransitOrderNumber
2. 中转收货页：确认到达 → 拆箱/拍照记录 → 提交 → 状态 `ready`（等待转发）
3. 中转发货页（订单/会话详情进入）：填物流公司 + 单号 + **物流费②** → `last_mile` → 顾客确认收货 `completed`

**归还（return）**：对称 —— 顾客归还发运（填单）→ 中转收货页（拍照）→ `ready` → 转发回商户（填物流公司/单号/**物流费④**）→ 商户验收 `completed`

## 6. 角色可见性

| 角色 | 可见 |
|------|------|
| 顾客 | 订单「已发货/归还中」+ 物流费合计（①+②+③）+ 中转网点名称/地址（收寄件地址） |
| 受控商户员工 | 订单/金额/中转网点单位名/地址/电话；**不可见下单人与顾客信息** |
| 中转员工 | 会话全量 + 顾客信息（物流面单所需）+ 扇出受控网点列表 |

## 7. 顾客端商户展示

- 受控商户乐器：商户显示「**合作商户**」占位 + 中转网点名称/地址（下单/归还寄送地址由后端按路由下发）
- 顾客下单操作与普通订单无差别（不感知商户与网点关系）
