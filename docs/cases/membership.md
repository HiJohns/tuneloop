# M-00 会员与乐币总纲

> **权威口径**：本文档对齐《平台会员规则与权益手册》（2026-09-01 起执行）。凡本文与旧文档（features.md §5.2 / cases.md 会员段）冲突，以本文为准。
> **设计准则（#1939，写入 AGENTS.md）**：手册给出的所有数值（比例/上限/门槛/效期）均视为**可调整**——必须提供后台配置功能与调整用例，禁止硬编码。

## 术语与单位

| 术语 | 定义 |
|------|------|
| 乐币 | 平台虚拟权益资产，**1 乐币 = 1 元人民币**；内部以分存储（`promo_points`），前端显示乐币 |
| 责任方 | 乐器丢失的责任归属：用户 / 物流公司 / 平台 / 网点 |
| 批次 | 一笔乐币获取的最小记账单元：`amount / remaining / acquired_at / expires_at` |

## 会员等级（M-01 晋升）

| 等级 | 晋升门槛 | 命名 |
|------|---------|------|
| 乐手会员 | 实名认证 + 手机绑定 + 会员费 99 元 | 默认（L1） |
| 首席会员 | 累计平台消费满 **5000 元** | L2 |
| 演奏家会员 | 累计平台消费满 **10000 元** | L3 |

## 关键规则

- **只升不降**：满足条件自动晋级，无降级机制
- **晋升违约校验**（M-08）：存在未结违约时**阻止晋升**（见 M-08 判定清单）
- **租金折扣**：首席 95 折 / 演奏家 9 折（定价引擎按会员等级折扣——**待立项**，见"未实现清单"）
- **累计消费口径**：`total_spending`（实付现金 C1，含租金/购物/购买乐币；**不含押金/物流费/维修费**）

## 乐币获取（M-02 批次获取）

| 途径 | 数额 | 到期日 |
|------|------|--------|
| 入会赠送 | 99 乐币 | 获取日 + **2 年** |
| 邀请奖励 | 10 乐币/人（上不封顶） | 获取日 + 2 年 |
| 裂变奖励（M-04） | 被邀请人有效消费 × 推荐人等级比例 | 获取日 + 2 年 |
| 平台活动 | 运营配置 | 运营配置 |
| 购买乐币 | 用户自选数额 | 获取日 + 2 年 |

## 乐币使用（M-03 抵扣）

- 抵扣范围：**仅租金**（初次付款/续期）；**不可抵扣**押金、物流费、维修费
- 抵扣上限：`A0 ≤ floor(应付租金 × 当前级别 pay_ratio)`；**pay_ratio 手册值 = 100%（全额抵扣），后台可调**
- 消费扣减顺序：**FIFO——先到期先扣**（同到期按获取时间）；每次扣减按批次留痕

## 乐币效期与过期（M-05）

- 每个批次：`acquired_at`（获取日）→ `expires_at`（获取日 + 2 年；**运营可调**）
- 余额 = **未过期批次 remaining 之和**（`users.promo_points` 为冗余快照，写路径同步维护）
- **过期清扫**：`remaining > 0 且 expires_at < now` → 清零留痕（`expired_cents`/`expired_at` + `points_transactions(type='expired')`）+ 余额扣减
- **到期提醒**：`expires_at - 30 天`推送提醒（复用 notifications + 小程序订阅消息）
- 找回/退回的乐币：**恢复原批次** remaining（保留原到期日）；原批次已清零部分不恢复（过期清零不可逆）

## 裂变奖励（M-04 推荐人返佣）

| 推荐人等级 | 比例（手册值，**可调**） |
|-----------|------------------------|
| 乐手 | **2%** |
| 首席 | **5%** |
| 演奏家 | **8%** |

- 基数：被邀请人的**有效消费**（租金；购物/购买乐币待商城/购买入口落地后纳入）
- **排除**：押金、物流费、维修费
- 触发：被邀请人订单**成功完结**时发放（完结后 15 天内有效即可，实现为完结即时）
- 受益人：**推荐人**（`referrals` 表回溯）
- 来源字段：`gift_policies.referral_ratio`（按推荐人级别，level-0 兜底）

## 退款差额结算（M-06，**取消"退款返点给自己"**）

- 付款 `R0 = C0 + A0` → 退款按调整后 `R1` 重算：`A1 = floor(R1 × pay_ratio)`
- `A1 < A0`：退 `A0−A1` 回批次 + 退 `C0−C1` 回微信；`A1 ≥ A0`：赠点不退
- **手册无"退款返点给自己"福利 → 已移除**（`refund_rebate`/`SelfSpendRatio` 分支废除）
- 保守校验：`退回乐币 + 退现金 = R0 − R1`

## 赠点策略配置（M-07，比例可调）

`gift_policies` 按会员级别（level-0 兜底）配置，PC「系统管理 → 赠点策略」维护：

| 列 | 手册默认 | 可调范围 |
|----|---------|---------|
| `pay_ratio` | **1.0（全额抵扣）** | 0 ~ 1.0 |
| `referral_ratio` | 乐手 0.02 / 首席 0.05 / 演奏家 0.08 | 0 ~ 1.0 |

- ~~`refund_ratio`（退款返点）~~：**字段废弃**（M-06 决策）
- 旧表 `membership_gift_ratios`（SelfSpendRatio/ReferralSpendRatio）**退役**

## 违约判定（M-08，晋升阻塞）

存在以下**任一**未结状态 → 阻止晋升：

| # | 违约项 | 数据判定 |
|---|--------|---------|
| 1 | 逾期未归还 | `orders.status = 'expired'` |
| 2 | 补缴未支付 | `order_payment_records.status='pending' AND order_type IN ('damage','repair','loss')` |
| 3 | 损坏流程未结 | `orders.status IN ('pending_damage_response','damage_appealing')` |
| 4 | 申诉未决 | `appeals.status IN ('pending','reviewing','forwarded')` |

> 口径 = **当前未结**（结清/归还后解除，可恢复）；与手册"历史无记录"字面差异已在发布条款中明确为"无未结记录"。
